# 第1章 全体像と用語

**学習目標**: ① RAGReel が何を入力に何を出力するか説明できる ② 登場する部品(PC側・クラウド側)の役割を言える ③ 以降の章で使う基本用語を知る

## 1.1 解決したい問題

Houdini などのツールは、手順を文章で読むだけだと分かりにくい。**手順を動画にして**、声で説明し、画面を見せたい。ただし動画を手で作るのは時間がかかる。
そこで RAGReel は次の流れを自動化する。

1. **知識を探す**: 質問に答えるために、社内/個人の知識ベース(Notion を Gemini で検索できるようにしたもの = **RAG**)から回答と出典を取る
2. **台本にする**: 回答を**スライド**に分け、読み上げる文章と、画面に出す要点・図・コードに整える
3. **声を付ける**: 文章を音声(WAV)にする
4. **絵を描く**: スライドを1フレームずつ描く(Qt の QML で。ブラウザもウィンドウも要らない = **ヘッドレス**)
5. **動画にまとめる**: 映像と音声を `.webm` にする
6. **公開する**: ギャラリーの Web ページに並べる(任意でクラウドにも置く)

## 1.2 部品と役割

![システム構成図](../diagrams/system-overview.svg)

| 部品 | 場所 | 役割 | 第 |
|---|---|---|---|
| **RAGReel.exe** | 利用者のPC | GUI ランチャー。設定を入れてエンジンを**子プロセスとして起動**するだけの薄い層 | 4 |
| **video_factory_cloudrag_poc.exe** | 利用者のPC | 動画を作る本体(エンジン)。CLI で動く | 4〜7 |
| **output/** | 利用者のPC | 動画・ダッシュボード・manifest の置き場(インストール先ごとに1つ) | 8 |
| **Cloud RAG** | Cloudflare | 質問に回答と出典を返す Worker(別リポジトリ DevelopmentRAGEnvironment) | 5 |
| **/tts** | Cloudflare | 文章を音声にする Worker(同上。中で Google Cloud TTS を呼ぶ) | 6 |
| **共有ギャラリー** | Cloudflare | 動画を URL で共有する Worker + R2(本リポジトリ `cloudflare/`) | 9 |
| **ダッシュボード** | `web/public/` | 動画を並べて見る静的な Web ページ | 8 |
| **compare/** | 利用者のPC | 同じ入力を3方式で動画にして比べる実験 | 10 |

**重要な設計判断**: C++ 側に検索エンジン(ベクトルDB)を埋め込まず、既存の Cloud RAG に **HTTP で聞くだけ**にした。C++ は HTTP クライアントに徹する。理由は、検索の更新(新しい知識)を RAGReel の再ビルド無しで反映できるから。

## 1.3 入力は2種類

| 入力 | 起動例 | 用途 |
|---|---|---|
| **質問文** | `video_factory_cloudrag_poc.exe "<質問>" <dbKey>` | 知識ベースへの質問から動画 |
| **Houdini のチュートリアル** | `--houdini-md <.md>`(+ `--houdini-json`、`--houdini-screenshots`、`--houdini-script`) | Houdini が生成した手順書と実画面から動画 |

どちらも `--mock` を付けると、ネットワークなしの固定データで動く(開発・確認用)。

## 1.4 最初に覚える言葉

| 言葉 | 意味 |
|---|---|
| **RAG** | Retrieval-Augmented Generation。質問に関係する資料を**先に検索**して、その内容を元に回答を作る方式。RAGReel の「R」 |
| **dbKey** | どの知識ベースに聞くかの名前(例: `houdini21`) |
| **Worker** | Cloudflare の、サーバー無しで動く小さなプログラム(JavaScript)。URL で呼べる |
| **R2** | Cloudflare のファイル置き場(S3 のようなもの)。動画を置く |
| **ヘッドレス** | 画面(ウィンドウ)を出さずに動くこと。RAGReel の描画はウィンドウ無しで、メモリ上の画像に描く |
| **QML** | Qt の宣言的な UI 記述言語。動画の1コマを QML で組み、フレームごとに値(見出し・進行度)を渡して描く |
| **スライド / 章** | 動画の1場面。ダッシュボードでは「章」と呼ぶ(章タイムラインの1区間) |
| **manifest** | 動画一覧の索引(`manifest.json`)。ギャラリーはこれを読んで並べる |
| **metadata** | 動画1本の詳細(`videos/<id>/metadata.json`)。章・出典・生成過程など |
| **パイプライン** | 取り込み → 構成 → … → 公開の、7段の処理の列 |
| **GPUリース** | 同時に1つの処理だけが GPU を使うための「貸出札」(第4章) |

## 1.5 本リポジトリの地図

```
engine/src/   C++ 本体(第4〜7章)
engine/qml/   動画の見た目(シーン)と GUI(第7章・第4章)
engine/tests/ 単体テスト(第11章)
web/public/   静的ダッシュボード(第8章)
cloudflare/ragreel-gallery/   共有ギャラリーの Worker(第9章)
compare/      3方式比較(Python)(第10章)
tools/        検査と図の生成(第11・12章)
docs/         技術リファレンス・この資料・図
installer/    Windows インストーラー(Inno Setup)
```

## 演習

1. 質問文を渡してから動画がギャラリーに並ぶまでを、7段のパイプライン名(第4章で詳しく)を知らなくてよいので、**自分の言葉で6行以内**で書け。
2. 「RAGReel.exe は動画を作らない」と言える理由を述べよ。
3. 検索エンジンを C++ に埋め込まなかった理由を1つ挙げよ。

## 解答(例)

1. 質問文 → Cloud RAG で回答と出典を得る → スライドに分けて台本にする → 音声にする → 1フレームずつ描く → 映像と音声を .webm にまとめて output/ に置き、ギャラリーに載せる。
2. RAGReel.exe は設定を集めてエンジン(video_factory_cloudrag_poc.exe)を子プロセスで起動するだけで、生成の処理自体はエンジンが行うから。
3. 検索の更新(知識の追加)を、RAGReel を作り直さずに反映できる。C++ の責務が小さくなり、保守が軽い。
