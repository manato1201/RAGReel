# 第3章 動画・音声・字幕の基礎

**学習目標**: 動画ファイルが何でできているかを理解し、RAGReel が「15fps・1280×720・VP9+Opus の .webm」を選んでいる理由と、時刻(秒・フレーム)の換算を説明できる。

## 3.1 動画は「連続した静止画 + 音声」

| 用語 | 意味 | RAGReel の値 |
|---|---|---|
| **フレーム** | 動画の1コマ(1枚の画像) | 1枚 = RGBA の画素の並び |
| **fps** | 1秒あたりのフレーム数 | 15(`main_cloudrag.cpp` の `kFps`) |
| **解像度** | 1フレームの横×縦の画素数 | 1280×720(`kFrameWidth/Height`) |
| **尺(長さ)** | 動画の秒数 | 音声の長さに合わせて決める |

**換算**: 全フレーム数 = 尺(秒) × fps。たとえば 84 秒なら 84 × 15 = 1260 フレームを描く。
**1秒の動画を作る時間**は、描く枚数(fps)に比例する。fps を 30 にすると、描画時間はおよそ 2 倍になる。

> なぜ 15 fps? 解説動画は動きが少ない(スライドの切り替えと進捗バー)ため、15 で十分に見え、生成が速い。滑らかな動きが要る遷移(第10章)を足すときだけ、上げることを検討する。

## 3.2 音声

- 音声は**サンプル**の列(1秒を何千回も測った値)。**サンプルレート**(例 24000 Hz、44100 Hz)が 1 秒あたりの個数。
- **WAV** は圧縮しない音声ファイル。ナレーションの途中成果物として WAV を作る。
- クラウド音声は 24 kHz の WAV で返るため、**44.1 kHz へ変換して連結**する(第6章)。サンプルレートが違うものをそのまま繋ぐと、速さと高さが変わる。
- 音声の長さ = サンプル数 ÷ サンプルレート。この**実測の長さ**から動画の尺を決める(動画を音声に合わせる。逆ではない)。

## 3.3 コンテナとコーデック

- **コーデック**: 映像/音声を小さくする方式(圧縮・展開)。
- **コンテナ**: 映像・音声・字幕を1つのファイルに入れる箱。

| | RAGReel の選択 | 理由 |
|---|---|---|
| コンテナ | **WebM** | ブラウザ(Houdini の内蔵ブラウザ含む)で再生できる |
| 映像 | **VP9**(libvpx) | ロイヤリティフリーで、ブラウザが標準で再生できる |
| 音声 | **Opus**(libopus) | 同上 |

過去には H.264 + AAC の MP4 だった。Houdini の内蔵ブラウザは H.264 を再生できない場合があるため、2026-08-28 に VP9 + Opus の WebM に変えた(技術リファレンス §20.7)。
**注意**: `avcodec_find_encoder(AV_CODEC_ID_OPUS)` は FFmpeg 内蔵の実験的エンコーダを選んでしまう。必ず**名前 `"libopus"` で探す**(`encode/video_encoder.cpp`)。

## 3.4 字幕

- 字幕は「いつ(開始・終了秒)・何を(文)」の組(**cue**)の列。
- ファイル形式は SRT・WebVTT。ブラウザは `<track>` か、`addTextTrack` + `VTTCue` で表示する。
- RAGReel の字幕は、**読み上げの時刻から作る**(第6章)。時刻が正確(VOICEVOX・クラウド)か概算(SAPI)かで、`subtitles_exact` を分けて記録する。
- `file://` で開くダッシュボードでは `<track src>` が読めないため、cue を `metadata.json` に埋め込んで JavaScript で付ける(第8章)。

## 3.5 色と画素

- フレームは **RGBA**(赤・緑・青・透明度、各 0〜255)。エンコーダは映像を **YUV420** に変えて圧縮する(`libswscale`)。
- 透明部分は黒になる(画像の透過を使うときは白地を敷く。ディスクのテクスチャで実際に起きた)。

## 3.6 時刻の換算(よく使う)

| したいこと | 式 |
|---|---|
| 秒 → フレーム | `round(sec × fps)` |
| フレーム → 秒 | `frame ÷ fps` |
| 章の終わり | `start_sec + duration_sec`(`metadata.json` の `chapters`) |
| スライドの境界 | `computeSlideStartFrames`(第5章)が、文字数の重みでフレーム番号を返す |

## 演習

1. 尺 120 秒・15 fps の動画は何フレームか。30 fps なら描画枚数はいくつ増えるか。
2. 24 kHz の音声に 44.1 kHz の音声を、変換せずに連結すると何が起きるか。
3. WebM を選んだ理由を、Houdini と関連づけて説明せよ。
4. ナレーションの文ごとの長さを測ると何に使えるか(2つ)。

## 解答(例)

1. 1800 フレーム。30 fps なら 3600 で、1800 枚増える。
2. 24 kHz 側が速く・高く再生される(サンプルの意味する時間が違うため)。必ず同じレートに変換してから連結する。
3. Houdini の内蔵ブラウザが H.264 を再生できない場合があり、VP9 + Opus の WebM ならロイヤリティフリーで再生できるため。
4. 動画の尺の決定と、字幕の cue の時刻(章タイムラインの境界にも使える)。
